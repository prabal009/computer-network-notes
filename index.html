Network Devices
Network Devices are the devices required for communication between computers on a computer network.


Enable communication by transmitting and receiving data between devices.
Allow devices to connect to networks efficiently and securely.
Improve network performance by reducing congestion and managing traffic.
Extend network coverage and solve signal loss

Layer 1 Devices: Physical Layer

These devices deal with raw electrical  signals (bits). These devices don't understand IP addresses or MAC addresses.

1. Hub

It is a central connection point for devices in a LAN.
It takes an incoming signal on one port and blindly broadcasts it to all other ports
High network traffic collisions and security risks (everyone sees everyone's data).

2. Repeater

It regenerates signals to extend the range of a network.
It receives a weak signal (due to attenuation over long cables), amplifies it, and retransmits it.
Extending WiFi range beyond 100 meters.


3. Modem (Modulator-Demodulator)

This bridges the gap between digital computer data and analog signals, allowing devices to connect to the internet via telephone, cable, or fiber lines.

Connects your home network to the ISP (Internet Service Provider).
Converts digital signals from your computer into analog signals for telephone/cable lines



Layer 2 Devices: Data Link Layer

These devices work with MAC Addresses (Physical Addresses). They are smarter than hubs.

4. Switch

A switch is a high-speed networking device that connects devices (computers, printers, servers) within a Local Area Network (LAN),
Unlike hub, switch learns the MAC address of every connected device.
It sends data only to the specific port
Reduces collisions and improves security and speed.

5. Bridge

This connects two separate LAN segments to make them appear as one.
Filters traffic based on MAC addresses to keep local traffic local, reducing congestion

6. Access Point (AP)

It is a networking hardware device that allows Wi-Fi-enabled devices, such as laptops and smartphones, to connect to a wired network.
Acts as a bridge between wired Ethernet and wireless Wi-Fi devices.
An AP only provides Wi-Fi signal and it does not route traffic or assign IP addresses.

Layer 3 Devices: Network Layer
These devices work with IP Addresses (Logical Addresses) and connect different networks together.

7. Router

It is a networking device that connects multiple networks and directs data packets between them using IP addresses.
It uses IP Addresses to determine the best path for data packets to travel
Routers stop broadcast traffic, isolating networks from each other.

8. Brouter (Bridging Router)

It is a networking device combining bridge and router functions, operating at both the Data Link and Network layers of the OSI model.
It can route known protocols (like TCP/IP).
It bridge unknown protocols and rarely used nowadays.

Layer 4-7 Devices: Advanced Processing

9. Gateway

It is a hardware device or software node that acts as an entry/exit point between two distinct networks using different protocols,
It can convert protocols, data formats,
An Internet Gateway translates your private LAN requests into public internet requests.

10. Firewall

It is a network security system, comprising hardware, software, or both that monitors and controls incoming and outgoing network traffic based on predetermined security rules

Network Models

Computer networks rely on these foundational frameworks to standardize communication. It explains the layered structures of the OSI and TCP/IP models and highlights how they organize network functions for efficient data flow.
OSI MODEL
Layers of OSI Model

The OSI (Open Systems Interconnection) Model is a 7-layer conceptual model that explains how data travels from one computer to another over a network. Each layer has a specific responsibility, making network communication organized

7. Application
6. Presentation
5. Session

Layer 1: Physical Layer

This is the lowest layer of the OSI model. It is responsible for transmitting raw bits (0s and 1s) over a physical medium such as cables, fiber optics, or wireless signals. It defines how devices are physically connected and the speed of data transmission. Devices like hubs, repeaters, modems, and cables work at this layer.

Example
When you plug an Ethernet cable into your laptop, the Physical Layer sends electrical signals through the cable.

Layer 2: Data Link Layer (DLL)

The Data Link Layer provides reliable communication between two directly connected devices. It adds MAC (physical) addresses, detects transmission errors, controls the flow of data, Devices such as switches and bridges operate at this layer.

Example

When your laptop sends data to your Wi-Fi router, the Data Link Layer ensures the packets of data reaches the correct device using MAC addresses.

Layer 3: Network Layer

The Network Layer is responsible for moving data between different networks. It assigns IP addresses, determines the best route for data, and forwards packets through routers. This is the layer that makes communication across the Internet possible.

Example

When you open www.google.com, the Network Layer routes your data through multiple routers until it reaches Google's server.

Device: Router

PDU: Packets

Layer 4: Transport Layer

The Transport Layer provides end-to-end communication between applications. It breaks large messages into smaller segments, reassembles them at the destination, ensures reliable delivery with TCP, or provides faster but less reliable delivery with UDP

Example

When watching YouTube, video streaming often uses UDP for speed, while downloading a file uses TCP to ensure every part arrives correctly.

Layer 5: Session Layer

The Session Layer manages the communication session between two applications. It establishes, maintains, synchronizes, and terminates sessions, and can insert checkpoints so interrupted transfers can resume instead of restarting.

Example

During a video call on Zoom or Google Meet, this layer helps maintain the communication session until the call ends.

PDU: Data

Layer 6: Presentation Layer

The Presentation Layer is often called the Translation Layer. It formats data performs encryption/decryption, and compresses/decompresses data so that different systems can understand each other.

Example

When you access a secure website using HTTPS, encryption (TLS/SSL) happens at this layer.

PDU: Data

Layer 7: Application Layer

The Application Layer is the topmost layer and is the one users interact with directly. It provides network services to applications such as web browsers, email clients, and file transfer software. Common protocols include HTTP, HTTPS, SMTP, FTP, DNS, and DHCP.

Example

When you open Chrome and visit a website

How Data Flows Through the OSI Model

Suppose you send an email to a friend.

Application Layer: You type the email and click Send.
Presentation Layer: The email is formatted and encrypted.
Session Layer: A communication session with the mail server is established.
Transport Layer: The email is divided into smaller segments.
Network Layer: IP addresses are added, and the best route is chosen.
Data Link Layer: Packets are converted into frames, and MAC addresses are added.
Physical Layer: Frames are converted into electrical, optical, or wireless signals and transmitted.

At the receiver's end, the process happens in reverse until the email is displayed in the recipient's inbox

TCP/IP Model

The TCP/IP (Transmission Control Protocol/Internet Protocol) Model is the networking model used by the Internet. It explains how data is sent from one device to another using 4 layers.
Unlike the OSI model (7 layers), TCP/IP has only 4 layers, making it simpler and more practical for real-world networking.

Why is it called TCP/IP?

It is named after its two most important protocols:

TCP (Transmission Control Protocol) → Ensures reliable communication.
IP (Internet Protocol) → Finds the destination and routes the data

What is SSL/TLS Encryption?

SSL (Secure Sockets Layer) and TLS (Transport Layer Security) are security protocols that encrypt data sent between a client (browser) and a server (website).
TLS is the newer and more secure version of SSL. Although SSL has been replaced by TLS, people still commonly say "SSL certificate" or "SSL encryption."
The main purpose of SSL/TLS is to make sure that no one can read, modify, or impersonate the communication between you and a website.
Encryption converts readable information (plaintext) into unreadable information (ciphertext) using a mathematical algorithm and a key.

Public Key and Private Key

SSL/TLS uses asymmetric encryption initially.

There are two keys:

Public Key
Can be shared with everyone.
Used to encrypt data.
Private Key
Secret and stored securely on the server.
Used to decrypt data encrypted with the matching public key.

Example:

Public Key
      │
Encrypt Data
      │
      ▼
Encrypted Data
      │
      ▼
Private Key
      │
Decrypt Data
      ▼
Original Data

Why Doesn't TLS Use Public-Key Encryption for Everything?

Public-key encryption is secure but slow.
After the browser and server securely exchange a shared secret, they switch to symmetric encryption, where both sides use the same secret key. Symmetric encryption is much faster and is used for the rest of the session.

My MAC Address is

AA:BB:CC:DD:EE:FF
Step 4

The computer stores the MAC address in its ARP cache and uses it to send frames.

WPA2 and WPA3 Explained

WPA2 and WPA3 are Wi-Fi security protocols used to protect wireless networks from unauthorized access. They encrypt the data transmitted between your device and the Wi-Fi router, making it difficult for attackers to read or steal the information.

WPA2 = Wi-Fi Protected Access 2 (introduced in 2004)
WPA3 = Wi-Fi Protected Access 3 (introduced in 2018)
WPA3 is the newer, more secure version of WPA2.

What is WPA2?
Definition

WPA2 (Wi-Fi Protected Access 2) is a Wi-Fi security standard that uses AES (Advanced Encryption Standard) to encrypt data between devices and the Wi-Fi router.

How WPA2 Works
You select your Wi-Fi network.
You enter the Wi-Fi password.
The router verifies the password.
If the password is correct, an encrypted connection is established.

Laptop
   │ Password
   ▼
Wi-Fi Router
   │
AES Encryption 🔒
   │
Internet

Features of WPA2
Uses AES encryption.
Requires a Wi-Fi password.

Advantages
Strong encryption.
Supported by most routers and devices.
Easy to configure.

Limitations
Uses a shared password (Pre-Shared Key) in home networks. If someone learns the password, they can join the network.
Susceptible to offline password-guessing attacks if users choose weak passwords.

What is WPA3?
Definition

WPA3 (Wi-Fi Protected Access 3) is the latest Wi-Fi security standard. It improves on WPA2 by providing stronger authentication, better encryption, and increased protection against password-guessing attacks.

Definition

If PC1 sends data, it travels along the backbone cable. Every device receives the signal, but only the intended recipient accepts it.

If the backbone cable fails, the entire network fails.
Performance decreases with heavy traffic.
Low security.

Carrier Sense Multiple Access (CSMA)
Definition

Carrier Sense Multiple Access (CSMA) is a Media Access Control (MAC) protocol used to control how multiple devices share the same communication channel.
Before sending data, a device first listens (carrier sensing) to check whether the communication channel is free.

If the channel is idle (free) → the device sends data.
If the channel is busy → the device waits until it becomes free.

This reduces the chances of collisions.
CSMA works at the Data Link Layer (Layer 2) of the OSI Model.

Why is CSMA Needed?
Imagine 10 computers connected to the same network.
If all computers send data at the same time:

PC1 ──►
PC2 ──►
PC3 ──►
PC4 ──►

All signals overlap.

This is called a collision.
The transmitted data gets corrupted and has to be sent again.
CSMA helps prevent this by making every device listen before transmitting.

How CSMA Works

Suppose four computers share one cable.

PC1 ---- PC2 ---- PC3 ---- PC4
Step 1

PC1 wants to send data.
It first checks the cable.
Cable Busy?
NO

Step 2
Since the cable is free,
PC1 starts transmitting.

PC1 ==========> PC4

Step 3
Now PC2 also wants to send.
It checks the cable.
Cable Busy?
YES
So PC2 waits.

Step 4
After PC1 finishes,
PC2 checks again.
Cable Busy?
NO
Now PC2 transmits.

Collision
Sometimes two computers check the cable at almost exactly the same time.

Example:

PC1

Checks → Free

PC2

Checks → Free

Both start sending simultaneously.

PC1 =========>

<========= PC2

Their signals collide.
This is called a collision.

Vulnerable Time
Even after sensing the channel, a collision can still happen.
This is because signals take time to travel.
This time is called the Propagation Time (Tp).

Example
Suppose:

PC1 ---------------------- PC2
Signal travel time = 5 μs
PC1 starts sending.
Before PC2 receives PC1's signal,
PC2 also thinks the channel is free.
Both transmit simultaneously.
Collision occurs.
The short period where this can happen is called the Vulnerable Time

Types of CSMA

There are two major protocols:

CSMA/CA

1. CSMA/CD (Collision Detection)

Full Form:
Carrier Sense Multiple Access with Collision Detection

Used in:

In wired Ethernet,

2. CSMA/CA (Collision Avoidance)
Full Form:

Used in:

Why Not Collision Detection?
Suppose your laptop is transmitting Wi-Fi signals.
Laptop ))))))))))
The transmitted signal is much stronger than any incoming signal.
While transmitting,
the laptop cannot accurately hear another device's transmission.
So it cannot reliably detect a collision.
Therefore,
Wi-Fi avoids collisions instead of detecting them.

Step 1
Device wants to transmit.

Step 2
Listen to the channel.
If busy,
wait.

Step 3
When free,
wait for a short time called

Step 4
Check again.
Still free?
Proceed.

Random Wait

Receiver sends

Success.

assume collision.
Retry.

Suppose
PC1 and PC2 both want to transmit.
Instead of sending immediately,
they choose random waiting times.

Example:

PC1 waits 2 slots

PC2 waits 8 slots

PC1 sends first.

PC2 waits.

No collision occurs.

RTS/CTS Mechanism

RTS = Request To Send
CTS = Clear To Send
Used to solve the Hidden Terminal Problem.

Step 1
Sender:
RTS
"I want to send."

Step 2
Receiver:
CTS
"You may send now."

Step 3
Other nearby devices hear the CTS and remain silent until the transmission is complete.

Hidden Terminal Problem
Imagine:

Laptop A      Router      Laptop C
A and C are both within range of the router, but A and C cannot hear each other.
Both think the channel is free.
Both send data.
Collision occurs at the router.

Using RTS/CTS helps avoid this situation.

Four Access Modes of CSMA

1. 1-Persistent CSMA
Listen continuously.
If channel becomes free,
send immediately.
Very aggressive.
Higher collision chance.

2. Non-Persistent CSMA
Listen once.
If busy,
wait a random time.
Then check again.
Fewer collisions.
More delay.

3. P-Persistent CSMA
Used in slotted systems.
When channel becomes free:
Transmit with probability P.
Wait with probability 1 − P.
Balances delay and collisions.

4. O-Persistent CSMA
A central controller assigns each device a transmission order or time slot.
Devices transmit only during their allocated turn.
This greatly reduces collisions but requires coordination.

Advantages of CSMA
Reduces collisions by sensing the channel first.
Improves network efficiency.
Simple and inexpensive to implement.
Works in both wired and wireless networks (with different variants).
Supports multiple devices sharing the same medium.

Disadvantages of CSMA
Performance decreases as the number of devices increases.
Devices may experience delays while waiting for the channel to become free.

DHCP Security Problems

1. DHCP Starvation Attack
An attacker sends thousands of fake DHCP requests using spoofed MAC addresses.

Fake Device 1

Fake Device 2

Fake Device 3
The DHCP server assigns all available IP addresses.

Result:

No IP addresses remain for legitimate users.

2. Rogue DHCP Server
An attacker installs a fake DHCP server on the network.
Instead of receiving the correct gateway and DNS, clients receive malicious settings.
This can redirect users to fake websites or route all traffic through the attacker.

3. Man-in-the-Middle (MITM) Attack
Using a rogue DHCP server, the attacker provides:
Fake gateway
Fake DNS
All network traffic passes through the attacker before reaching its destination.

4. DNS Misuse
The attacker provides a malicious DNS server.
When the user types:
google.com
the fake DNS may redirect them to a phishing website.

Protection Against DHCP Attacks

1. DHCP Snooping
Switches allow DHCP responses only from trusted ports connected to legitimate DHCP servers.
This blocks rogue DHCP servers.

2. Port Security
Limits the number of MAC addresses allowed on a switch port, helping prevent DHCP starvation attacks.

3. Rate Limiting
Restricts the number of DHCP requests a device can send in a given time.

4. Monitoring and Logging
Administrators monitor DHCP lease logs to detect suspicious activity such as abnormal numbers of requests or unauthorized servers.

Advantages of DHCP
Automatically assigns IP addresses.
Prevents duplicate IP addresses.
Reduces manual configuration.
Simplifies network management.

Disadvantages of DHCP
If the DHCP server fails, new devices may not receive IP addresses.
Lacks built-in authentication, making it vulnerable to attacks like rogue DHCP servers.

System Bus Design
System Bus Design (Easy Explanation)
A System Bus is a set of communication pathways (wires or traces) that connects the CPU, Memory (RAM), and Input/Output (I/O) devices. It allows these components to exchange information.

What is a System Bus?
A System Bus is a collection of parallel wires.

Each wire carries 1 bit.
If there are 8 wires, it is an 8-bit bus.
If there are 16 wires, it is a 16-bit bus.
If there are 64 wires, it is a 64-bit bus.
More wires mean more data can be transferred at once.

Why is it called a "Shared Bus"?
Only one device can use the bus at a time.
Imagine a single-lane bridge.
CPU is sending data → Others must wait.
Hard disk is sending data → CPU waits.
This prevents two devices from sending data simultaneously and causing collisions.

Three Types of System Bus
A system bus consists of three types of lines:
Address Bus
Data Bus
Control Bus

1. Address Bus
Purpose
The Address Bus tells where the data should go.
It carries the memory address from the CPU.
Direction
Unidirectional
CPU  ─────────► Memory

Only the CPU sends addresses.
Memory never sends addresses back.

Example
Suppose the CPU wants data stored at memory location 500.
The CPU sends:
Address = 500
using the Address Bus.
Now RAM knows which location the CPU wants.

Why is it Important?
The number of address lines determines how much memory can be accessed.

Formula:
Maximum Memory = 2^(Number of Address Lines)

Example
16 address lines
2^16 = 65,536 addresses

Data Bus
The Data Bus carries the actual data.
This is the information being transferred.
Direction
Bidirectional
CPU ◄────────► Memory
Both CPU and memory can send data.

Example 1 (Reading)
CPU asks RAM:
Give me the value at address 100.
RAM sends
25
through the Data Bus.

Why is Data Bus Width Important?
The width determines how much data can be transferred at one time.

Example
8-bit Data Bus
Transfers 8 bits at once
A wider data bus generally means higher performance because more data moves in each transfer.

3. Control Bus
The Control Bus carries control and timing signals.
It tells every component what operation to perform and when.
Think of it as the traffic police of the system bus.

Example
Suppose CPU wants to read data.
The CPU sends:
Memory Read
through the Control Bus.
RAM understands:
"The CPU wants to read data."

If CPU wants to store data:
Memory Write
RAM understands:
"Store the incoming data."

CPU → RAM

"Store this data."

CPU → Keyboard
"Send your data."

"Print this."

Interrupt Request (IRQ)
Sometimes a device needs immediate attention.

Example:
You press a key.
Keyboard sends
Interrupt Request
The CPU pauses its current task and processes the keyboard input.

Clock Signal
The clock synchronizes all operations.

Bus Request / Bus Grant
If multiple devices want to use the bus:
A device sends a Bus Request.
The CPU or bus controller sends a Bus Grant.
Only then can that device use the bus.
This avoids conflicts.

Why is the Control Bus Important?
Without the Control Bus:
RAM wouldn't know whether to read or write.
Devices would act at the wrong time.
Multiple devices could try to use the bus simultaneously.

What is UTP (Unshielded Twisted Pair)?
UTP (Unshielded Twisted Pair) is the most commonly used networking cable. It consists of pairs of insulated copper wires twisted together without any additional metal shielding.

Why are the wires twisted?
Suppose there is a nearby power cable.
A straight wire would pick up electrical noise.

When two wires are twisted:

Both wires experience nearly the same interference.
The receiver compares the signals.
The common interference cancels out.
This results in a cleaner, more reliable signal.

Both WDM (Wavelength Division Multiplexing) and DWDM (Dense Wavelength Division Multiplexing) are technologies used in optical fiber communication.

Multiplexing means combining multiple signals into one communication channel.

Example
Imagine a highway.
Without multiplexing → Only one car can use the road.
With multiplexing → Many cars travel together on the same highway

What is WDM?
WDM (Wavelength Division Multiplexing) is a technology that combines multiple light signals of different wavelengths (colors) and sends them through one optical fiber.
Each wavelength carries its own independent data.

Why use WDM?
Without WDM:

Fiber 1 → Signal A
Fiber 2 → Signal B
Fiber 3 → Signal C
Need three separate fibers.

With WDM:
Signal A
Signal B
Signal C
      │
      ▼
One Optical Fiber
Only one fiber is needed.
This reduces installation cost.

Advantages of WDM
1. Increased Capacity
Many signals travel simultaneously.
More data.

2. Cost Effective
No need to install multiple optical fibers.

Disadvantages of WDM
Difficult wavelength tuning
Mostly suitable for smaller networks

What is DWDM?
DWDM (Dense Wavelength Division Multiplexing) is an advanced version of WDM.

The word Dense means:
More wavelengths are packed very closely together.
Instead of using only a few wavelengths,
DWDM uses dozens or even hundreds of wavelengths on the same optical fiber.

Data Link Layer in OSI Model
The Data Link Layer is the second layer of the OSI (Open Systems Interconnection) Model.
It is responsible for transferring data between two directly connected devices (node-to-node communication) on the same local network (LAN).

Main Responsibilities of the Data Link Layer
The Data Link Layer receives packets from the Network Layer, converts them into frames, and sends them to the Physical Layer for transmission.

It performs the following tasks:
Node-to-node delivery
Framing
Physical (MAC) addressing
Error detection and correction

2. Physical Addressing (MAC Address)
Every network device has a unique MAC Address.

Example:
00:1A:2B:3C:4D:5E
The Data Link Layer uses MAC addresses to deliver frames within the same LAN.

3. Error Detection
Sometimes data becomes corrupted during transmission.
The Data Link Layer detects errors using techniques like:
CRC (Cyclic Redundancy Check)
Checksum
The receiver detects that the data has changed.

Sub-layers of Data Link Layer
The Data Link Layer has two sublayers.

Data Link Layer
│
├── Logical Link Control (LLC)
│
└── Media Access Control (MAC)

1. Logical Link Control (LLC)

LLC is responsible for:
Multiplexing
Flow control
Error reporting

Example
Computer A sends data.
Computer B replies:
ACK
This acknowledgment is handled by LLC.

2. Media Access Control (MAC)

The MAC sublayer is responsible for:
MAC addressing
Frame creation

It decides:
"Which device can send data now?"

Devices Operating at Data Link Layer

1. Switch
A switch is the most common
It forwards frames using MAC addresses.

Example

The switch learns MAC addresses and sends the frame only to the correct destination.

2. Bridge
A bridge connects two LANs.
It reduces unnecessary traffic by forwarding only required frames.

3. Network Interface Card (NIC)
Every computer has a NIC.

Functions:
Stores the MAC address.
Sends and receives frames.
Connects the computer to the network.

4. Wireless Access Point (WAP)
Allows wireless devices to communicate with a wired network.
Protocols Used at Data Link Layer

Some common protocols include:
HDLC (High-Level Data Link Control) – Reliable communication over point-to-point links.
PPP (Point-to-Point Protocol) – Commonly used for direct connections (e.g., older dial-up and some WAN links).
SLIP (Serial Line Internet Protocol) – Older protocol for serial connections.
SDLC (Synchronous Data Link Control) – IBM-developed data link protocol.
LCP (Link Control Protocol) – Establishes and manages PPP links.
NCP (Network Control Protocol) – Configures network-layer protocols over PPP.

What is SDLC?
SDLC (Synchronous Data Link Control) is a Data Link Layer (Layer 2) protocol developed by IBM
Its main purpose is to provide reliable communication between devices by organizing data into frames and detecting transmission errors.

It supports:
Point-to-Point communication
Multipoint communication

Basic SDLC Frame Format
An SDLC frame looks like this:

+------+---------+---------+-------------+------+------+
|Flag  | Address | Control | Information | FCS  | Flag |
+------+---------+---------+-------------+------+------+

Every field has a specific purpose.

1. Flag Field
Purpose
The Flag Field marks the beginning and end of every frame.

Flag Pattern
The flag is always:
01111110
This special bit pattern helps the receiver recognize where a frame begins and ends.
Without the flag, the receiver wouldn't know where one frame ends and the next begins.

2. Address Field
Purpose
The Address Field tells which device should receive the frame.

Example
Suppose three computers exist:
Computer A
Computer B
Computer C
Address field:
Address = Computer B
Only Computer B processes the frame.
The others ignore it.

Types of Addressing

Individual Address
Sent to one device.

Example:
Address = PC2

Group Address
Sent to multiple devices.

Example:
Address = Lab Computers

Broadcast Address
Sent to everyone.

Example:
Address = All Devices

3. Control Field
This is one of the most important fields.
It tells the receiver:
"What should I do with this frame?"

Types of SDLC Frames

There are three frame types.

A. Information Frame (I-Frame)

Used to carry actual user data.
The Control field identifies it as an I-Frame.

Uses
Data transfer

B. Supervisory Frame (S-Frame)

Used for:

Acknowledgement
Error reporting

It does not carry user data.

Uses
ACK
NAK

C. Unnumbered Frame (U-Frame)

Used for connection management.

Examples

Establish connection
Disconnect connection
Reset communication

It is mainly used for control purposes

Uses
Link setup
Link termination

4. Information Field
Purpose
This field contains the actual data.

5. Frame Check Sequence (FCS)
Purpose
The FCS detects transmission errors.

Before sending:
The sender calculates an error-checking value using a method such as CRC (Cyclic Redundancy Check).
The receiver performs the same calculation.
If both values match:
✅ Data is correct.
If not:
❌ Error detected.

6. Ending Flag
The ending flag is exactly the same as the starting flag.
01111110
It tells the receiver:
"The frame has finished."

Complete Example
Suppose Computer A sends:
Hello
The SDLC frame becomes:

+--------+---------+-----------+-------------+------+--------+
| Flag   | Address | Control   | Information | FCS  | Flag   |
+--------+---------+-----------+-------------+------+--------+
|01111110| PC2     | I-Frame   | Hello       | CRC  |01111110|
+--------+---------+-----------+-------------+------+--------+

Serial Line Internet Protocol (SLIP)
SLIP (Serial Line Internet Protocol) is one of the earliest protocols used to send IP packets over a serial connection.

Why was SLIP created?
In the early days of the Internet, computers were connected using serial communication (telephone lines, RS-232 serial ports, dial-up modems).
However, the IP protocol could not directly send packets

It simply says:
"Take an IP packet, add start/end markers, send it over the serial cable."

SLIP was mainly used in:
Serial ports (RS-232)
Router-to-router communication
Host-to-host communication
Early UNIX systems

Today, it has almost completely been replaced by PPP (Point-to-Point Protocol)

How does SLIP work?
Suppose the IP layer creates an IP packet.
SLIP simply adds a special byte at the end.
When the receiver sees the END byte, it knows:
"The packet is finished."

A major job of SLIP is framing.
Framing means:
Determining where one packet starts and where it ends.
SLIP uses two special control characters.

1. END Character
Purpose:
Marks the end of every packet.

2. ESC Character
Purpose:
Used when the actual data itself contains an END or ESC byte.
Otherwise, the receiver would mistake it for a control character.

Instead of sending

END

it sends

ESC ESC_END

Similarly,

Instead of sending

ESC

it sends

ESC ESC_ESC

Addressing
SLIP cannot automatically assign IP addresses.
Both devices must already know each other's IP addresses.

Data Transmission
SLIP sends
IP Packet
+
END

Nothing more.
A SLIP frame looks like:

+--------------------+
|     IP Packet      |
+--------------------+
|      END Byte      |
+--------------------+

Very simple.

Advantages of SLIP

1. Very Simple
Easy to implement.
Very little code is required.

2. Low Overhead
Adds only a few extra bytes.

3. Lightweight
Suitable for devices with limited memory and processing power.

Disadvantages of SLIP

1. No Authentication
Anyone connected to the serial line can communicate.

2. Supports Only IP

4. No Dynamic IP Address Assignment
IP addresses must be configured manually.

3. No Error Detection
If bits are corrupted during transmission,
SLIP does not detect or correct errors.

Why was PPP introduced?

SLIP had many limitations.
PPP (Point-to-Point Protocol) improved on SLIP by adding:

Authentication (PAP, CHAP)
Dynamic IP address assignment
Error detection
Support for multiple network protocols

The two most common authentication methods are:

PAP (Password Authentication Protocol)
CHAP (Challenge Handshake Authentication Protocol)

Think of them as two different ways of proving your identity.
Why is Authentication Needed?
Suppose you dial into an Internet Service Provider (ISP).
Before allowing access, the ISP wants to verify your identity.

1. PAP (Password Authentication Protocol)
PAP is the simplest authentication protocol.
It works like logging into a website using a username and password.

How PAP Works
Client connects to the server.
Client sends:
Username
Password
Server checks the credentials.
If correct → Access granted.
If incorrect → Access denied.

Problem with PAP
The password is sent in plain text.
If an attacker intercepts the communication, they can directly read the password.

Advantages of PAP
Very simple
Easy to implement
Fast authentication

Disadvantages of PAP
Password sent in plain text
Vulnerable to eavesdropping

2. CHAP (Challenge Handshake Authentication Protocol)
CHAP is much more secure.
Instead of sending the password, it proves the client knows the password without actually transmitting it.

How CHAP Works
Step 1: Connection Established
Client ------------- Server
Step 2: Server Sends a Challenge
The server generates a random number.

Example:
Challenge = 56789
and sends it to the client.

Step 3: Client Creates a Hash
The client combines:
Challenge
Password

Example:
Password = abc123
Hash(56789 + abc123)
Suppose the result is:
8A92BC41
The client sends only:
8A92BC41
The password itself is never sent.

Step 4: Server Verifies
The server already knows the user's password.
It performs the same calculation:
Hash(56789 + abc123)
If the computed hash matches the client's hash:
Authentication Successful
Otherwise:
Authentication Failed
